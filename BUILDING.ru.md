## Общие сведения

Для Windows, Linux и macOS используется один общий исходный файл Python — `JBPad.py`. В репозитории находятся шесть спецификаций PyInstaller (`.spec`): по две для Windows, Linux и macOS.

- Сборка **`onedir`** размещает исполняемый файл и его зависимости в каталоге или пакете приложения.
- Сборка **`onefile`** упаковывает исполняемый файл и его зависимости в один исполняемый файл. В macOS результатом при этом остаётся пакет приложения `.app`.

Сборки Linux и macOS типа `onefile` используются как компоненты общей сборки **All_OS**. Сами по себе они не являются полными дистрибутивами JBPad.

## Окружения сборки

Сборку следует выполнять в целевой операционной системе, используя совместимые версии Python и PyInstaller. Эти спецификации не предназначены для кросс-компиляции.

Ниже перечислены окружения, в которых проверялась сборка проекта:

| Цель            | Проверенное окружение                                                                     |
| --------------- | ----------------------------------------------------------------------------------------- |
| Windows 7+ x86  | Windows 7, Python 3.8.10 x86, PyQt5 5.15.2 / Qt 5.15.2, PyInstaller 6.22.3                |
| Windows 10+ x64 | Windows 10 22H2, Python 3.11.9 x64, PyQt5 5.15.11 / Qt 5.15.2, PyInstaller 6.18.0         |
| Linux           | Linux Mint 22.2 x86_64, Python 3.12.3, PyQt5 5.15.11 / Qt 5.15.19, PyInstaller 6.22.0     |
| macOS           | macOS Ventura 13.2 x86_64, Python 3.11.15, PyQt5 5.15.11 / Qt 5.15.19, PyInstaller 6.22.0 |

Работа готовой программы также проверялась на Windows 7, 10 и 11; Linux Mint 22.2 (X11) и Fedora Workstation 44 (X11 и Wayland); macOS Ventura 13.2 и Sequoia 15.1. Проверка работы программы в этих системах не означает, что каждая из них использовалась для сборки каждого дистрибутива.

Для сборки Windows 7 x86 использовался Python 3.8.10, поскольку это последний выпуск Python с поддержкой Windows 7. Окружение Windows 7 отличается от окружения для более новых версий Windows.

В проведённых для проекта сборках Python 3.11.9–3.12.3 и PyInstaller 6.18.0–6.22.3 работали без заметных различий для Windows 10+, Linux и macOS. Это наблюдение по проверенным окружениям, а не гарантия полной взаимозаменяемости всех сочетаний этих версий.

Виртуальное окружение (`venv`) можно использовать для изоляции зависимостей проекта, но сами `.spec`-файлы не требуют его обязательного применения. Установите Python, PyQt5 и PyInstaller в то окружение, которое собираетесь использовать.

## Подготовка к сборке

1. Установите совместимую версию Python в целевой операционной системе.
2. Установите PyQt5 и PyInstaller в используемое для сборки окружение Python.
3. Убедитесь, что в корне репозитория находятся необходимые элементы:
   - `JBPad.py`
   - `Data/` — необходима для сборок `onedir`; сборки `onefile` не копируют её.
   - `resources/`
   - `build/`
4. Откройте терминал в **корне репозитория** — каталоге, в котором находится `JBPad.py`.

Спецификации используют текущий рабочий каталог для поиска файлов проекта. Запуск из другого каталога может привести к неправильному разрешению путей.

## Команды сборки

Запускайте соответствующую команду из корня репозитория.

### Windows 7+ x86

```bash
python -m PyInstaller --clean --noconfirm build/Windows/JBPad_Windows7.spec
```

Используйте совместимое 32-разрядное окружение сборки для Windows 7.

### Windows 10+ x64

```bash
python -m PyInstaller --clean --noconfirm build/Windows/JBPad_Windows10.spec
```

### Linux — `onedir`

```bash
python -m PyInstaller --clean --noconfirm build/Linux/JBPad_Linux.spec
```

### Linux — `onefile`

```bash
python -m PyInstaller --clean --noconfirm build/Linux/JBPad_Linux_onefile.spec
```

### macOS — `onedir`

```bash
python -m PyInstaller --clean --noconfirm build/macOS/JBPad_macOS.spec
```

### macOS — `onefile`

```bash
python -m PyInstaller --clean --noconfirm build/macOS/JBPad_macOS_onefile.spec
```

Если команда `python` запускает не то окружение, в котором установлены необходимые зависимости, укажите соответствующий интерпретатор Python. Например, в Windows можно использовать `py -3.11 -m PyInstaller` или полный путь к нужному интерпретатору.

По умолчанию PyInstaller размещает промежуточные файлы в `build/`, а результаты дистрибутива — в `dist/`. Точная внутренняя структура зависит от версии PyInstaller и конкретной спецификации; ориентируйтесь на фактический результат сборки и приведённую ниже таблицу.

## Результаты сборки

| Спецификация                           | Тип сборки | Цель            | Основной результат                                            | Обработка `Data/`                              |
| -------------------------------------- | ---------- | --------------- | ------------------------------------------------------------- | ---------------------------------------------- |
| `build/Windows/JBPad_Windows7.spec`    | `onedir`   | Windows 7+ x86  | `dist/JBPad/`, включая `JBPad.exe` и `_Windows7+_x32/`        | Копирует исходную `Data/` в `dist/JBPad/Data/` |
| `build/Windows/JBPad_Windows10.spec`   | `onedir`   | Windows 10+ x64 | `dist/JBPad/`, включая `JBPad.exe` и `_Windows10+_x64/`       | Копирует исходную `Data/` в `dist/JBPad/Data/` |
| `build/Linux/JBPad_Linux.spec`         | `onedir`   | Linux           | `dist/JBPad/`, включая исполняемый файл `JBPad` и зависимости | Копирует исходную `Data/` в `dist/JBPad/Data/` |
| `build/Linux/JBPad_Linux_onefile.spec` | `onefile`  | Linux           | Исполняемый файл `dist/JBPad`                                 | Не копирует `Data/`                            |
| `build/macOS/JBPad_macOS.spec`         | `onedir`   | macOS           | `dist/JBPad.app/` и `dist/Data/`                              | Копирует исходную `Data/` в `dist/Data/`       |
| `build/macOS/JBPad_macOS_onefile.spec` | `onefile`  | macOS           | `dist/JBPad.app/`                                             | Не копирует `Data/`                            |

Все шесть спецификаций включают `resources/` в сборку PyInstaller и явно указывают скрытый импорт `PyQt5.sip`. Точное расположение включённых ресурсов внутри дистрибутива может зависеть от структуры PyInstaller; не следует считать, что `resources/` обязательно находится рядом с исполняемым файлом.

Спецификации **не копируют** `Setting.ini` и файлы лицензий. Они добавляются отдельно при подготовке дистрибутива.

### Повторная сборка и `Data/`

Каталог `Data/` внутри результатов `onedir` пересоздаётся при сборке; изменения в этой копии не следует использовать как постоянное хранилище данных.

Спецификации Linux и macOS `onefile` намеренно не копируют `Data/`: соответствующие исполняемые компоненты используются при формировании All_OS, где имеется один общий каталог `Data/`.

## Подготовка платформенных компонентов

Имена, создаваемые PyInstaller, являются именами результатов сборки и могут отличаться от окончательных имён в релизе. Для официальной общей сборки All_OS подготовьте компоненты следующим образом:

| Платформа       | Компонент для All_OS                 | Источник                                                                 |
| --------------- | ------------------------------------ | ------------------------------------------------------------------------ |
| macOS           | `JBPad_macOS.app/`                   | Сборка macOS `onefile` (`dist/JBPad.app/`, переименовывается для релиза) |
| Linux           | `JBPad_Linux`                        | Сборка Linux `onefile` (`dist/JBPad`, переименовывается для релиза)      |
| Windows 10+ x64 | `_Windows10+_x64/` и `JBPad_x64.exe` | Сборка Windows 10+ `onedir`                                              |
| Windows 7+ x86  | `_Windows7+_x32/` и `JBPad_x32.exe`  | Сборка Windows 7+ `onedir`                                               |

Для Windows спецификации создают исполняемый файл `JBPad.exe`; при подготовке релиза он переименовывается в `JBPad_x64.exe` или `JBPad_x32.exe`. Для Linux сборка `onefile` создаёт файл `JBPad`, который переименовывается в `JBPad_Linux`. Для macOS пакет приложения создаётся как `JBPad.app` и переименовывается в `JBPad_macOS.app`.

Эти суффиксы — соглашение об именовании релизных компонентов. Сами по себе они не меняют исходный код программы или её поведение.

## Сборка All_OS

All_OS объединяет перечисленные выше платформенные компоненты с общими файлами. Она собирается из результатов соответствующих платформенных сборок и не создаётся одной-единственной `.spec`-спецификацией.

Общие элементы:

- `Data/`
- `LICENSE`
- `LGPL-3.0.txt`
- `Licenses.txt`
- `Setting.ini` (необязательный, но присутствует в официальном дистрибутиве)

Используйте платформенные исполняемые файлы и каталоги зависимостей из соответствующих сборок. Общие элементы берите из корня репозитория или из подготовленных релизных файлов. Каталог `Data/` общий для всех платформ и должен присутствовать в общей сборке только один раз — на общем уровне. Достаточно одной общей копии `Data/`.

Каталог `resources/` — общий исходный ресурс, который используется платформенными сборками и включается спецификациями. В приведённый выше перечень отдельных общих файлов All_OS он не входит.

## Важные замечания

- Собирайте программу в целевой ОС и совместимом окружении: эти спецификации не обеспечивают кросс-компиляцию.
- Запускайте команды PyInstaller из корня репозитория.
- Не считайте результат `onedir` одним самостоятельным исполняемым файлом: его зависимости также входят в дистрибутив.
- Сборки Linux и macOS `onefile` используются как компоненты All_OS, а не как готовые пакеты All_OS.
- `Setting.ini` и файлы лицензий необходимо добавлять отдельно при подготовке релиза.
- Создание установщика Windows — необязательный этап. Инструкции по использованию настроенного проекта CreateInstall приведены в файлах [`README.ru.md`](packaging/Windows/CreateInstall/README.ru.md) и [`README.md`](packaging/Windows/CreateInstall/README.md).
